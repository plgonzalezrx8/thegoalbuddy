01 / Find your bearings

Three ways to move forward.

You do not need to learn the internal roles to begin. Choose the situation you are in.

01

Start

Install from this checkout, restart your coding tool, then tell Goal Prep what you want to achieve and how you will know it worked.

In the repository terminal · Node 18+

Installs both tools. Limit to one with --target codex or --target claude.

Codex$goal-prep
Claude Code/goal-prep

Prep creates the goal files and prints the command to begin execution. It does not start the work itself.

02

Resume

Find your existing goal and its active task. Continue from the same local files, even if you switch coding tools.

In the repository terminal

Use the exact continuation command printed for your tool. The goal's files carry the context forward.

Codex uses native /goal when available. Claude Code uses the installed /goalbuddy command.

03

Unblock

Inspect the blocked task and read its reason, stop condition, and receipt. Give the coding tool the missing decision, access, or evidence.

“Here is the answer to the blocked task: …”

Use the continuation command printed by Resume and add your answer. The coding tool updates the goal state and continues from the recorded next step.

The browser is a viewer. It does not approve decisions, edit tasks, or run your coding agent.

Fork preview: thegoalbuddy has not been published to npm by this change. Use the checkout command above. The familiar npx thegoalbuddy path is for a future published release.

Already using upstream GoalBuddy?

Disable the upstream goalbuddy@goalbuddy Codex plugin before enabling thegoalbuddy@thegoalbuddy, to avoid duplicate $goal-prep entries. Shared goal_* agent files and compatibility CLI names overlap; keep one package/plugin active in a home, or use separate homes. See the README for installation and migration details.

03 / Keep your bearings

The sky changes.
Your files stay.

Your coding tool reads and updates a small workspace inside the repository. The local browser viewer follows those files; it does not replace them.

goal.md

The destination: what you want, what is in scope, and the observable result that proves success.

state.yaml

The current position: tasks, dependencies, active work, blockers, and receipts.

notes/

The observations: longer findings, verification output, and evidence for the next handoff.
