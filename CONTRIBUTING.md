# Contributing to thegoalbuddy

**Keep your goal in sight.** Improve the local observatory, its execution safeguards, and the handoff between Codex and Claude Code. Follow the accepted [Constellation Observatory identity](https://github.com/plgonzalezrx8/thegoalbuddy/blob/main/BRANDING.md) and preserve the upstream MIT attribution.

## Local setup

Use Node 18 or later; a maintained Node 22 or 24 release is recommended. Install the pinned development dependencies without setting up either coding tool in your own home (POSIX shell):

```bash
git clone https://github.com/plgonzalezrx8/thegoalbuddy.git
cd thegoalbuddy
GOALBUDDY_SKIP_POSTINSTALL=1 npm ci
npm run build
npm run typecheck
npm run check
```

All maintained program code, tests, fixtures, and build/release tools are TypeScript. Edit `.mts` Node sources and `.ts` browser sources; never edit their generated `.mjs`/`.js` outputs. The compiler is a development dependency. Installed users run generated runtime with plain Node and do not need a compiler.

`npm run build` compiles staged outputs and refreshes the canonical skill mirror. `npm run check:generated` verifies committed outputs without repairing drift. `npm run check` performs the pre-packaging checks and behavior suites; it creates no npm tarball and publishes nothing. A failed or interrupted generation must be recovered through the build tool before accepting the output as current.

## Skill tree and tests

`goalbuddy/` is the canonical skill tree. `plugins/goalbuddy/skills/goal-prep/` is its generated byte-identical mirror; edit only the canonical source. Generated installable runtime remains committed because native plugins can be installed from Git without an npm build step.

Use the focused suites after a scoped edit:

```bash
npm run test:skill
npm run test:cli
npm run test:release
npm run test:board
npm run check:generated
```

Final acceptance also requires genuine Codex and Claude installation checks, browser verification, and independent review of the exact source revision. Unit tests do not establish authenticated coding-tool execution or a working hosted website.

## Isolated install check

thegoalbuddy installs into both tools by default; `--target` selects one. Keep test homes separate from your real installation. After building from the repo root:

```bash
# Both targets; Codex needs a CLI with native marketplace support.
install_root=$(mktemp -d)
node internal/cli/goal-maker.mjs --codex-home "$install_root/codex" --claude-home "$install_root/claude"
node internal/cli/goal-maker.mjs doctor --target codex --codex-home "$install_root/codex"
node internal/cli/goal-maker.mjs doctor --target claude --claude-home "$install_root/claude"
rm -rf "$install_root"

# Claude files can also be checked before the host is installed.
claude_test_root=$(mktemp -d)
node internal/cli/goal-maker.mjs install --target claude --claude-home "$claude_test_root"
node internal/cli/goal-maker.mjs doctor --target claude --claude-home "$claude_test_root"
rm -rf "$claude_test_root"
```

These checks inspect installed files. Executing a goal requires the corresponding authenticated coding tool and any account-gated feature it uses.

## Website and branding

The website source lives in `internal/site/`; `npm run build:site` produces its static `dist/` export for Sites. Run `npm run check:branding` and `npm run check:site` before browser checks and deployment. Use the actual assigned Codex subdomain, preserve the chosen audience, and follow [site hosting](https://github.com/plgonzalezrx8/thegoalbuddy/blob/main/internal/site/DNS.md). Keep goal data, credentials, tests, and release evidence out of the deployment export.

Label screenshots as examples, retain visible keyboard focus and reduced motion, and distinguish the local read-only viewer from coding-agent execution. Historical upstream release art and compatibility identifiers remain intact.

## Final npm artifact and publication

Complete TypeScript, generated/mirror, behavior, host/browser, hosted Sites, and independent-review checks first. Readiness evidence must match the exact current inputs. Only then create the final npm artifact and run `npm run check:package` against it. Preserve its integrity and test the same file through isolated installation; never replace it with a fresh pack between verification and publication.

Publication requires explicit authorization and a successful `publish:check` for the verified artifact. See [the release process](docs/releases/README.md). Do not use routine source checks or website deployment as permission to publish, and do not enable automatic publication without matching readiness evidence available to that workflow.

## Contribution boundaries

- Keep installed runtime dependency-free and the canonical skill installable.
- Preserve both coding-tool targets, `goalbuddy`/`goal-maker` compatibility aliases, and Goal Prep as the single prep skill.
- Keep goal files authoritative and local; never commit local `docs/goals/` run artifacts unless requested.
- Preserve user-owned configuration and upstream attribution.
- Update instructions when behavior changes and run `npm run check` before claiming completion.
